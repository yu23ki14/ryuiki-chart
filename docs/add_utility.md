# 事業体を 1 つ追加する手順

水道水の水源マップ（`docs/WATER_SOURCE_MAP.md`）に、新しい水道事業体を足すときの手順。
企業団・横浜市（Phase 1）と県営水道（Phase 2）を実際に足して固まったもの。

**1 事業体 = 1 タスク。** 出力は設計図 §8 の 4 点セット
（CSV の追記・`data/raw/water/<utility>/` の原本・`reports/<utility>.md`・検証の通過ログ）。

---

## 0. 先に決めること

| | |
|---|---|
| `utility_id` | `UTL_<英字>`（例 `UTL_KENEI`）。`kind` は `bulk`（卸）か `retail`（末端給水） |
| id の接頭辞 | 施設は `FAC_<3〜4文字>_`（`FAC_YOK_` / `FAC_KGD_` / `FAC_KEN_`）。資料は `DOC_<同>_` |
| 原本の置き場 | `data/raw/water/<utility>/`（Git 管理外） |

**水源（`water_source`）は既存を再利用する。** 相模川・酒匂川・道志川はもう入っている。
同じ川に別の id を作らない。ダム・湧水など新しいものだけ足す。

---

## 1. 給水区域の粒度を最初に見極める

**ここで手順が 3 つに分かれる。先に調べる。** 順に当たるとよい。

| 粒度 | 使うもの | 例 |
|---|---|---|
| **市町村単位で公表** | `zone_rule.csv` に 1 行書く | 県営水道（「県営水道の給水区域」ページ。12市6町） |
| **町丁目単位で公表** | `zone_assignment.csv` に直接書く | まだ無い。情報公開請求で出てきたらここ |
| **図しか無い** | ラスタ読み取り（§3-b） | 横浜市（水質検査計画の「各水源の主な給水区域」図） |
| **何も無い** | 割り付けない。問い合わせに積む | — |

**「一部」給水の市町村に注意。** 「○○市（一部）」は市全体のルールを書いてはいけない。
詳細ページの町名を `zone_assignment.csv` に町丁目単位で書く。
小字単位（「中津のうち箕輪下原」など）まで細かいものは**町丁目に落ちないので割り付けない**。

**政令指定都市に注意。** e-Stat の `city_name` は `相模原市緑区` のように区単位。
`city_exact 相模原市` は 1 件も当たらない（検証がエラーで教えてくれる）。

## 2. 上流（水源 → 取水 → 浄水場）を作る

読む資料はだいたいこの 3 つ。

| 資料 | 何が載っているか |
|---|---|
| **水質検査計画** | 水源の系統と保有水源量、浄水場ごとの原水と取水地点、給水区域図 |
| **事業概要 / 事業年報** | 給水系統図、浄水場別の浄水量・受水量（`basis=measured` にできる数字） |
| **卸元の事業概要** | 受水している場合、卸元のどの浄水場から何を受けているか |

**給水系統図が最重要。** ただし縦書きでテキスト抽出が崩れることが多い。
`pdftoppm -f <頁> -l <頁> -r 170 -png` で画像にして読むこと（企業団 p49・p50 がまさにこれ）。

`flow_edge` の書き方:

- `share` は「**to_id に入る水のうち何割が from_id 由来か**」。出て行く側の分岐ではない。
- **同じ `to_id` × 同じ有効期間の share は合計 1.0。** 検証で落ちる。
- 上流が複数あって比率が公表されていないときは **junction（`type=junction`）を 1 つ作る**。
  次の 3 つを順に検討する。
  1. **上流が全部同じ水源なら**、比率を知らなくても答えが確定する（県営の `FAC_KEN_SAGAMIKEI`）
  2. **水源が違い、施設能力比などで概算が置けるなら** `basis=nominal`。note に「概算」と書く（企業団の導水路）
  3. **水源が違い、置ける根拠が無いなら `basis=unknown`**（下記）
- `basis`: `measured`（年報の実測）/ `estimated`（系統図から読めるが数値の裏付けが無い）/
  `nominal`（施設能力比などの概算）/ `unknown`（顔ぶれは確定・混合比は非公表）。
  **推測で `measured` を付けない。**

#### `basis=unknown` — 比率は出さないが顔ぶれは出す

資料が「この市には寒川浄水場西系と企業団伊勢原の水が入る」と**顔ぶれまでは言っているのに、
何割ずつかは言っていない**、という状態が頻出する。全部「不明」にすると資料が言っていることまで
捨てることになり、平均や按分で埋めると捏造になる。**比率だけ黙る**のが正解。

- **`share` は空にする。** 0.5 や施設能力比で埋めると検証がエラーにする
- **同じ流入先に、比率のある行と `unknown` の行を混ぜてはいけない**（検証がエラーにする）。
  混ぜると片方だけ % が出て、残りが 0% なのか不明なのか読めない
- 合成は、経路に `unknown` が 1 本でもあればその町丁目の水源を**全部まとめて比率なし**にする
- 地図では関係する水源の色の**斜めストライプ**で塗られ、カードは % を出さずに
  「混合比は公表されていません」と出る。実装は `web/src/lib/map/stripe.ts`

**`nominal` と `unknown` は別物。** 施設能力比で概算が置けるなら `nominal`（「概算」ラベルが付く）。
置ける根拠が無いなら `unknown`。迷ったら `unknown` の方が安全。

**顔ぶれ自体が不確かなら `unknown` にも載せない。** それは「割り付けない」（§3-c）。
県営の二宮町・大磯町は、平塚配水池が企業団伊勢原からも受けているか断定できず、
`unknown` ではなく未割付にした。

## 3. 割り付ける

### 3-a. 市町村単位（`zone_rule.csv`）

```
rule_id,match_type,match_value,facility_id,share,confidence,valid_from,valid_to,source_doc_id,note_ja
R_KEN_FUJISAWA,city_exact,藤沢市,FAC_KEN_SAGAMIKEI,1.0,medium,2026-04-01,,DOC_KEN_NENPO_R4,…
```

- `match_type` は `city_exact` / `city_prefix` / `key_prefix`
- `match_value` は **`data/processed/estat_shozaiki_kanagawa.csv` の `city_name` と突き合わせてから書く**。
  表記ゆれがある（「保土ケ谷区」「東ケ丘」の「ケ」）。1 件も当たらないルールは検証がエラーにする
- `source_doc_id` は必須。無い行はビルドで落ちる

### 3-b. 図しか無いとき（ラスタ読み取り）

`scripts/c92_water_trace_yokohama.py` が実装。手順は同じでよい:
図を 420dpi で画像化 → 凡例の色に分類 → **実際の市町村外形と最も重なる変換を IoU 最大化で探す**
→ 町丁目ポリゴン内の色を多数決。

**やること 2 つ。**
1. `confidence` を**ポリゴン内の色の純度で段階化**する（0.95 以上 → `medium`、0.5 以上 → `low`、
   0.5 未満 → 行を作らない）。`high` は付けない。
2. **公表されている文章（浄水場ページの「〜区に給水」など）と突き合わせて一致率を測り、report に書く。**
   横浜は 90.2% だった。IoU ではなくこの一致率で位置合わせを選ぶこと
   （横浜では回転を足すと IoU は上がったのに一致率が下がった）。

### 3-c. 割り付けないという判断

**「不明」は不明のままにする**（設計図 §6-3）。0.5/0.5 や人口比で埋めない。

判断は 2 段。**まず水源の顔ぶれが資料で確定できるかを見る。**

| | |
|---|---|
| 顔ぶれ ○ / 比率 ○ | 普通に割り付ける |
| 顔ぶれ ○ / 比率 ×（非公表） | **`basis=unknown` で割り付ける**（§2） |
| 顔ぶれ × | **割り付けない** |
| 給水区域が小字・番地単位で町丁目に落ちない | **割り付けない** |

**カバレッジの目標に届かせるために 1 段目を緩めない。** 県営の相模原市緑区は、区内だけで
5 系統（落合＝栃谷川 / 鎌沢＝佐野川 / 和田＝沢井川 / 鳥屋＝早戸川 / 谷ケ原＝相模川）が
名指しされているため、区を 1 つの junction にすると橋本の住民に栃谷川を見せることになる。
これで CP2 の 70% に 1.5pt 届かなかったが、緑区は入れなかった。
割り付けなかった市町村は **理由を 1 行ずつ `reports/<utility>.md` に書く**。
これが次に何を請求すればよいかのリストになる。

## 4. 通す

```bash
.venv/bin/python scripts/c91_water_docs.py     # 資料を取って source_doc.csv を作り直す
.venv/bin/python scripts/m06_water.py --dry-run # 検証。エラー 0 になるまで直す
.venv/bin/python scripts/m06_water.py           # ryuiki.sqlite に入れる
cd web && node scripts/build-water-geo.mjs && pnpm run prepare:geo
```

`--dry-run` が見るもの: 主キー重複 / 語彙外 / 外部キー切れ / 水源の自己参照の閉路 /
**share 合計 ≠ 1.0** / 期間の逆転 / `source_doc_id` 無し / 当たらない `zone_rule`。

`m06_water.py` は最後に**人口ベースの割付率と市区町村別の内訳**を出す。
CP の判定はこの人口の方で見る（町丁目の数は面積も人口もばらばらで意味が薄い）。

## 5. 報告する

`reports/<utility>.md` に、`reports/kenei.md` と同じ構成で:

1. 読んだ資料と使ったページ
2. 採用した数値と根拠ページ、`basis` の内訳（measured / estimated / nominal の本数）
3. **名寄せ失敗リスト**（無ければ「なし」と明記）
4. **割り付けなかった市町村と、その理由 1 行ずつ**
5. 判断に迷った点、`confidence` の内訳
6. 未確認・問い合わせが必要なもの（必要なら `reports/inquiry_<utility>.md` に文面を下書き。**送信しない**）

## つまずいたところ（実例）

- **同じ名前の浄水場が 2 つある。** 寒川浄水場は県営と企業団の両方にある（同じ寒川町宮山）。
  県営が企業団から浄水委託を受けている関係で、**別事業**。施設を分け、繋がなかった。
  小雀浄水場も横浜市と企業団の両方にあるが、原水が同じ相模川なので 1 つにまとめた。
  **同名だから同一視、もその逆もしない。資料で確かめる。**
- **卸の水が末端の配水系統に浄水のまま入る。** 企業団相模原浄水場の横浜市向け給水地点の名前が
  「西谷」「川井」で、横浜市の同名の浄水場の配水系統に企業団の浄水が混ざっている。
  給水区域図の凡例が「**主に**道志川系統の水」と書いているのはこれ。
  受水量が分からないと直せない。**「○○浄水場系＝水源 100%」は上限だと思っておくこと。**
- **区・市町村の境と系統の境は一致しない。** 横浜市青葉区は図の上で北東半分が別系統だった。
  浄水場ページの「青葉区に給水」という記述の方が粗い。**粗い方に合わせない。**
