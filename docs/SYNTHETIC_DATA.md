# 合成データ設計書（流域カルテ デモ）

このドキュメントは `scripts/s01_synthetic.py` が生成した合成データ（`is_synthetic=1`）の
生成ロジック・パラメータ・参照した実データを、第三者が再現できる粒度で記録する。
検証は `scripts/s99_validate_synthetic.py` で行う。

**担当範囲**: 要求定義書（`app_description.md`）のデータモデル要求（§6）のうち、
公開データには原理的に存在しない要素（観測者・機器校正・現地測定イベント・品質遷移履歴・
介入記録・意思決定記録・OGC SensorThings 形式のセンサー時系列）。
`sites` / `measurements`（環境省公共用水域水質等）/ `organism_records`（GBIF/iNaturalist）/
`protocols` / `taxa` / `source_registry` は既存の実データ収集パイプライン（`scripts/c*.py`, `m01〜m04`）
の担当であり、本ドキュメントの対象外（`sites.treatment` 列の更新のみ例外。§0参照）。

## 実行方法・再現性

```
. .venv/bin/activate
python scripts/s01_synthetic.py          # 生成（冪等: 既に生成済みのテーブルはスキップ）
python scripts/s99_validate_synthetic.py # 検証
```

- 乱数シードは `SEED = 20260829` に固定（`scripts/s01_synthetic.py` 冒頭）。
- サイト・観測者・日付はすべて固定リスト・固定順序で走査するため、同じ乱数シードで
  再実行すれば同一の結果になる。
- 生成は `INSERT OR IGNORE` のみで行い、`UPDATE`/`DELETE` は使わない
  （唯一の例外は §0 の `sites.treatment` 列）。各テーブルは「既に `is_synthetic=1` の行が
  存在するか」で生成済みかどうかを判定し、再実行時は二重生成しない。

## §4. events / measurements（現地測定イベント・測定値）

### 4.1 スケジュール

各イベント地点（24件）に対して、`EVENT_START=2023-09-01` から `EVENT_END=2026-08-29`
（＝タスク実行日）まで、約6週間間隔（±5日のジッタ）で定期観測イベントを生成し、
10%の確率で欠測（スキップ）させた。結果として **定期観測イベント 565件** が生成された。

これとは別に、FR-1.8「降雨イベント連動」のデモとして、`data/processed/jma_daily_yokohama.csv`
の実測日別降水量（`variable=precipitation_total`）が **30mm/日以上だった実測37日**の
**翌日**に、相模川水系18地点のうち3地点（37日を3地点ずつ巡回的に選定、重複排除）で
`is_rain_triggered=1` の臨時観測イベントを生成した（**111件**）。`precip_24h_mm` には
その実測値をそのまま格納している（例: 2026-06-03 の166.0mm→2026-06-04のイベントに166.0を格納）。

合計イベント数: **676件**（定期565 + 降雨トリガー111）。

- `protocol_id` は既存の実在プロトコル `kanagawa_river_citizen_survey__manual`
  （県民参加型調査 調査マニュアル、神奈川県環境科学センター）のみを使用。存在しない
  protocol_id は作成していない。
- `weather` は、イベント日が `jma_daily_yokohama` の収集範囲（2024-01-01〜2026-08-28）内
  であれば実測の `weather_summary_day`（日中天気概況）をそのまま採用。範囲外
  （2023-09〜2023-12）は `["晴","曇","雨","晴時々曇","曇時々雨"]` からランダムに選択
  （実測が存在しないための代替であることを明記する）。
- `precip_24h_mm` は、降雨トリガーでない通常観測では実測値が存在すればそれを、
  存在しない日（JMA収集範囲外、または当日値が欠測）は 0〜5mm の一様乱数
  （小雨〜無降雨相当の参考値）で代用。**降雨トリガーイベントは常に実測値**。
- `is_backfilled=1`（紙記録の後追い入力, FR-1.11）は定期観測イベントの**10%**に付与
  （実測: 676件中57件 ≒ 8.4%）。
- `gps_offset_m`（FR-1.4 GPS検算）は、96%のイベントで `min(|N(5,4)|, 15.0)`（0〜15m中心）、
  残り4%で `Uniform(55,160)`（50m超の警告デモ）とした（実測: 676件中24件 ≒ 3.6%）。

### 4.2 観測体制（FR-1.5: 1地点2名以上）

各イベント地点に「プライマリチーム」（測定者1名＋立会者1名）を固定的に割り当て
（`ordinary`＝初級+訓練済プールからのラウンドロビン）。**全イベントに必ず測定者1名＋
立会者1名以上（`event_observers` に distinct observer_id が2名以上）**を記録している
（`s99_validate_synthetic.py` で検証済み・0件の違反）。

### 4.3 測定項目とロール別粒度（FR-1.9）

主測定者の role によって記録する変数セットを変えている（役割によって入力項目の
粒度を出し分けるFR-1.9のデモ）。

| role | 測定変数 |
|---|---|
| 初級 | 気温・水温・pH |
| 訓練済 | 上記＋溶存酸素量DO・浮遊物質量SS |
| 専門 | 上記＋COD・BOD（全7項目） |

この7変数（`air_temp, water_temp, ph, dissolved_oxygen, cod, bod, suspended_solids`）は、
すべて実データ（環境省 公共用水域水質測定, `measurements.is_synthetic=0`）に対応する
変数が存在するものだけを採用した。県民参加型調査マニュアル本文が明記するのは
気温・水温・pHの3項目のみだが、本アプリのデモ範囲としては「水質計」機器（多項目プローブ）
を想定し、DO/COD/BOD/SSを実データ分布に基づいて拡張している（マニュアル原文の
測定項目とは異なる、意図的なスコープ拡張であることをここに明記する）。

### 4.4 実データ由来の分布（乱数生成の根拠）

各変数の値は、`measurements` テーブルの実データ（`is_synthetic=0`, 値が非NULL）から
算出した平均・標準偏差を用いた正規分布 `N(mean, std)` からサンプリングし、
`VARIABLE_CLIP` の物理的妥当範囲でクリップした（`scripts/s01_synthetic.py::real_stats()`,
`sample_value()`）。

再現用クエリ:
```sql
SELECT AVG(value), <母標準偏差>, MIN(value), MAX(value)
FROM measurements WHERE variable_en=? AND is_synthetic=0 AND value IS NOT NULL;
```

| variable_en | n(実データ) | mean | std(母標準偏差) | min | max |
|---|---|---|---|---|---|
| air_temp | 7651 | 18.7091 | 8.3654 | -3.2000 | 39.0000 |
| water_temp | 9291 | 17.8062 | 6.1208 | 2.3000 | 34.0000 |
| ph | 33328 | 7.9438 | 0.3522 | 6.4000 | 10.0000 |
| dissolved_oxygen | 36301 | 8.5890 | 1.9949 | 0.0000 | 23.0000 |
| cod | 35084 | 2.8975 | 1.9252 | 0.0000 | 48.0000 |
| bod | 26667 | 1.5224 | 1.5696 | 0.0000 | 42.0000 |
| suspended_solids | 24160 | 4.3322 | 8.1324 | 0.0000 | 310.0000 |

（2026-08-29時点のDBスナップショットで算出。実データが増える場合、
`scripts/s01_synthetic.py` は実行時に毎回このクエリを再計算するため、値は自動的に
最新の実データに追従する。）

**水温だけは特別扱い**: 同一イベント内で気温・水温の両方が実測されている実データ
（`is_synthetic=0`, n=9109）から単回帰した実データ由来の関係式

```
water_temp = 6.0928 + 0.6324 * air_temp + N(0, 2.9753)
```

を用いて生成した（`real_paired_airtemp_watertemp()`）。これにより、合成イベントの
気温と水温が実データと同じ関係性を持つ。

### 4.5 意図的な外れ値（FR-1.7）

全測定値の**約3%**（`OUTLIER_RATE=0.03`、実測: 2265件中78件 ≒ 3.4%）を、
`mean ± (3.2〜4.5)×std` の範囲に意図的にシフトした値として生成している
（`source_ref` に `outlier_by_design(FR-1.7 demo)` と明記）。これは
「入力値が過去分布から外れた場合、その場で再測定を促す」機能のデモ用データ。

### 4.6 ペア測定（FR-2.4: 同一地点の複数測定者間の一致率）

定期観測イベント565件の**約10%**（`PAIR_EVENT_RATE=0.10`。降雨トリガーイベントは対象外）で、
プライマリチーム以外の観測者（訓練済/専門プールから
ランダム選出）が同一イベント・同一項目を独立に再測定したレコードを追加した。
2つの値の差は、変数ごとに以下のジッタ幅で決めた（実データの残差程度の小さいブレを想定）。

| variable | ジッタ | 内容 |
|---|---|---|
| air_temp / water_temp | 絶対値 ±N(0,0.5)°C | |
| ph | 絶対値 ±N(0,0.2) | |
| dissolved_oxygen | 絶対値 ±N(0,0.4) mg/L | |
| cod / bod | 相対値 ±15% | |
| suspended_solids | 相対値 ±20% | |

`source_ref` に `paired independent measurement (FR-2.4 demo) of <元measurement_id> by <observer_id>`
と記録し、追跡可能にしている。

### 4.7 対策区への意図的効果付与（BACI デモ用, FR-3.2）

石積み対策区（道志橋・弁天橋）では、施工開始日（`interventions.started_on`）以降に
生成される `suspended_solids`（浮遊物質量SS）の値を **15%低減**させている
（`TREATMENT_SS_EFFECT=0.85`）。これは**実際の観測結果ではなく、BACI比較ダッシュボードの
デモが成立するように意図的に注入した効果**であり、実際の環境改善効果を主張するものでは
ない。対照区（沼本ダム・名手橋）にはこの効果を適用していない。

## §5. quality_transitions（品質段階の遷移履歴）— FR-2.1 / FR-2.2

合成 measurements（2265件）それぞれについて、以下のロジックで遷移履歴を生成した
（`assign_quality_transitions()`）。**対象は合成データのみ**。実データ
（`measurements.is_synthetic=0`, 313,053件）は既に全件 `公開済` として収集されており、
過去の遷移履歴を持たない（いつ検証されたかの実データが存在しないため、
架空の履歴を実データ行に付与することはしていない＝実データを一切書き換えない
という絶対条件と整合）。

1. **初期提出**: 全measurementに `暫定` への初期遷移（`from_stage=NULL, to_stage=暫定`,
   `actor=現地測定者`, `occurred_at=measured_on`）。
2. **専門家抜き取り検証**（FR-2.2「専門家が抜き取り対象を抽出」）: 全measurementの
   **35%**（`REVIEW_SAMPLE_RATE`）をランダムに抜き取り、`研究監修`ロールの観測者が
   `measured_on + 3〜30日後` に検証。
   - **合格率80%**（`REVIEW_PASS_RATE=0.80`）で `暫定→検証済`。
   - 不合格（20%）は `暫定→暫定`（差し戻し。`note='専門家検証: 差し戻し(再測定を推奨)'`）。
3. **公開**: 検証済のうち**55%**（`PUBLISH_AFTER_PASS_RATE`）が、`検証済日+5〜60日後` に
   `CfJ運営`ロールの観測者によって `検証済→公開済` に遷移。

**設計意図**: FR-2.2 は「専門家検証通過率」の目標を80%以上としている。合格判定確率を
80%ちょうどに設定しているのは、目標値そのものを再現するための意図的な設計であり、
「達成できていることを示すための後付け調整」ではなく「目標値を体現するデモデータを
作る」という设計方針である。実行結果（763件抜き取り、630件合格）の通過率は
**82.57%**（二項分布のサンプリング誤差の範囲内で80%前後）。

`measurements.quality_stage` / `verified_by` / `verified_on` は、上記遷移履歴の最終状態と
必ず整合するように、生成時に一度に確定させている（後からのUPDATEは行っていない）。

駆除対象種はスクミリンゴガイ（*Pomacea canaliculata*, ジャンボタニシ）。神奈川県内の
`taxa` テーブルに実在する外来種（`ias_category` 該当）で、`organism_records` にも
iNaturalist由来の実在観察記録が12件ある（ただし個体数・密度は記録されていないpresence-onlyデータ）。

**organism_records は新規生成していない**: 上記の実在Pomacea記録は個体数・密度が
すべてNULL（iNaturalist由来のpresence-onlyデータのため）であり、密度の実データ分布が
存在しない。「適当な数字を作らない」という絶対条件に従い、根拠のない密度・個体数を
捏造するよりは、駆除の事実（捕獲重量・人日）のみを `interventions` に記録するに
とどめた。これは意図的なスコープ限定であり、タスク仕様の8項目（observers/instruments/
events/measurements/quality_transitions/interventions/decisions/sensor_timeseries）には
含まれていない。

## §7. decisions（意思決定記録）— 14件

要求定義書 §6「データモデルの一級市民」、M-B KPI「データが意思決定の場に持ち込まれた
回数＝累計12回」に対応させ、**14件**（目標12件以上）を生成した（`build_decisions()`）。

- 会議名はすべて**架空**（例:「（架空）相模川中流域流域協議会 定例会」
  「（架空）秦野市 環境審議会 令和7年度第1回」「（架空）道志川地区 寄合」）。
  神奈川県内で実際にありうる会議体（流域協議会・市の環境審議会・地区の寄合・
  自然再生検討委員会）を模しているが、**実在の会議・実在の決定を記録したものではない**
  ことを、会議名の「（架空）」表記と `source_ref`（`synthetic; 会議名・出席区分は
  いずれも架空`）の両方で明記している。
- `participants` は「現地PM, 研究監修, 集落住民代表」のような**役割ベースの表記**のみで、
  実在の個人名は使用していない。
- `presented_data`（JSON文字列）には、その会議に関連する対策区の `site_id` と、
  同地点・同時期の合成 `measurement_id` を2〜3件埋め込んでいる。特定の対策区に
  紐づかない全体会合は、定期観測イベント地点の代表 `site_id` を参照する。
  5件目の会議には、実在する Pomacea canaliculata の観察記録
  （`organism_records`, `is_synthetic=0`）のIDも1件添えた。
  → `s99_validate_synthetic.py` で、これらの参照が全て実在するIDであることを検証済み。
- `stalled_item_resolved=1`（停滞していた案件が実行に至った）は14件中5件。
  「BACI比較設計」「未校正機器の校正前倒し」「石積みのSS低減傾向の確定」など、
  複数回の会議をまたいで停滞していた案件が実行段階に進んだ、という筋書きにしている。

## §8. sensor_timeseries（合成センサー）— 19,420行

FR-4.3「OGC SensorThings API 形式で保持・提供」のデモ用。

- **水温ロガー**（`datastream='water_temperature'`）: 道志橋・弁天橋・寒川取水堰(上)の
  3地点。`data/processed/jma_daily_yokohama.csv` の実測日別平均気温
  （`air_temp_mean`, 2024-01-01〜2026-08-28, 971日, 欠損なし）を §4.4 の実データ回帰式
  `water_temp = 6.0928 + 0.6324*air_temp + N(0, resid_std*0.4)` に通し、
  6時間ごと（1日4点）に日周変動 `0.6*sin(2π*h/24)` を加えて生成。
  **実測の気温と相関させる**という要求を、実データから推定した回帰係数で満たしている。
- **土壌水分計TDR**（`datastream='soil_moisture'`）: 復田対策区2地点（尾山耕地・青根）。
  貯留・減衰モデル `moisture(t) = 0.94*moisture(t-1) + 0.01*precip(t) + N(0,0.005)`
  （`precip`は同じくjma_daily_yokohamaの実測日降水量、欠測日は0mm扱い）で、
  降雨後に上昇し緩やかに減衰する物理的に妥当な挙動を再現。値は `[0.10, 0.55] m3/m3` に
  クリップ。要求定義書は水温についてのみ「気温と相関させる」ことを明記しているが、
  土壌水分は気温よりも降水量との連動が物理的に妥当なため、実測降水量を用いた
  精度確保の代替ロジックを採用した（本文にその理由を明記）。
- 生成期間はJMA実測気温データの収集範囲（2024-01-01〜2026-08-28）に限定し、
  それ以前（2023-09〜2023-12）は生成していない（実測気温が存在しない期間に
  相関を主張しないため）。

**既知の非対象事項（本タスクでは修正していない）**: `sensor_timeseries` の実データ
（`is_synthetic=0`）側に、`sagamihara_taiki_hourly` / `soramame_hourly_kanagawa` 由来の
344,137行が `sites` テーブルに未登録の観測局IDを参照している孤児行として存在する。
これは本合成データ生成より前から存在する、別の収集エージェントの成果物における
データ品質の問題であり、本タスク（公開データに存在しない要素の合成）の対象外である。
実データを書き換えないという絶対条件により、この問題を修正するための `sites` への
INSERT等も行っていない（該当観測局を新規サイトとして登録するかどうかはデータモデル
オーナーの判断が必要なため）。

**チェックサムに関する制約**: `s99_validate_synthetic.py` は実データ行
（`is_synthetic=0`）のチェックサムを `data/logs/synthetic_validation_snapshot.json` に
保存し、以後の実行で差分が無いことを継続的に検証する仕組みを持つ。ただし、時間的制約により
`s01_synthetic.py` を初めて実行する**前**の状態のチェックサムは取得できなかった
（本ドキュメント作成の時点で `s01_synthetic.py` は既に実行済みだったため）。
その代わりに、(a) `s01_synthetic.py` のコード中に `UPDATE` 文が
`sites.treatment` の1箇所しか存在しないことをコードレビューで確認していること、
(b) タスク開始時点で提示された実データの件数（sites 352 / measurements 313,053 /
sensor_timeseries 377,378 / organism_records 451,108 / taxa 8,364 / protocols 6 /
source_registry 93 / events 29,271）が現在の `is_synthetic=0` 件数と完全に一致していること
（`s99_validate_synthetic.py` §2で検証）の2点から、実データ行が意図せず変更されていないことを
担保している。
