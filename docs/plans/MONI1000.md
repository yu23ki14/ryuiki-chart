# モニタリングサイト1000（モニ1000）神奈川県5出典を D1・MCP に載せる設計

ブランチ feat/moni1000。設計担当の作成（2026-10-12）。実装は下の §6 の担当ごとの節に従う。

## 0. 前提（決定済み）

- 組織の追認済み（2026-10-12、オーナー確認）。隔離（`redistributable=0`）を解いて D1・MCP に載せる。**新たな取得はしない**
  （フォーム送信・再ダウンロードをしない）。入力は手元の `data/processed/moni1000_*_kanagawa.csv` だけ。
- 対象 5 出典: `moni1000_satochi_bird`（18,396）/ `moni1000_satochi_butterfly`（14,529）/ `moni1000_forest_bird`（9,433）/
  `moni1000_satochi_mammal`（2,031）/ `moni1000_coast_shorebird`（620）。計 44,999 行。`moni1000_lake_*` 等の 0 件出典は対象外。
- 載せ方はツキノワグマ目撃の前例どおり「生の表 ＋ 出現記録」。生の表を D1 に置き `get_records` で全行取れるようにし、
  同時に manifest で occurrence に流して `get_occurrences` の集計（種一覧・年別・流域）にも出す。
- v2 の L2（observation/occurrence/occurrence_place）は D1 に入れない方針を維持。座標はぼかさない。

  （S060・S065 蝶類・S071 は NULL）。**丸め値をそのまま持ち、補完・ぼかしはしない**。精度は `coordinate_uncertainty_m`（小数桁数から機械的に: 1 桁=10,000、2 桁=1,000、4 桁=10）で出現側に渡す。

## 2. 生の表・書き手・D1・レジストリ

### 2.1 1 表に統合する（`moni1000_counts`）

出典別 5 表にしない。理由: (a) 5 出典とも「調査 × 地点 × 種 × 個体数」の同じ形で、共通列が 15 列以上ある。
(b) `get_records` は `record_set` ごとに 1 つの `RECORD_TABLES` 定義が要り、出典は `source_id` 列で絞る既存の方式（`wildlife_sightings` と同じ）。
5 表だと access.yaml の `record_sets`・records.ts・TABLE_ORIGIN・schema.ts・テストが 5 倍になる。
(c) 出典固有の列は `extra_json` に収める（列の多くが他出典で NULL になる表は作らない）。
record_set 名は `monitoring_counts`、表名は `moni1000_counts`。

```sql
-- scripts/schema_moni1000.sql
CREATE TABLE IF NOT EXISTS moni1000_counts (
  record_id TEXT PRIMARY KEY,        -- satochi 3 出典: '{source_id}:{data_id}'。他: '{source_id}:r{6桁連番}'
  source_id TEXT NOT NULL, source_ref TEXT,
  survey_id TEXT,                    -- 調査 ID（satochi 3 出典。他は NULL）
  site_key TEXT NOT NULL,            -- 出典の地点キー（S060 / 100246 / 130700）
  site_name_ja TEXT,
  place_id TEXT,                     -- registry の place（地点対応表で結ぶ。無ければ NULL）
  lat REAL, lon REAL,                -- 出典の値のまま（丸め・補完・ぼかしをしない）
  lat_lon_basis TEXT,                -- 'row'（行に在る）/ 'site_table'（sites CSV）/ NULL
  coord_decimals INTEGER,            -- 小数桁数（精度の根拠）
  coordinate_uncertainty_m REAL,     -- 小数桁 d から 10^(5-d) m。座標が無ければ NULL（m10 が計算し、adapter は写すだけ）
  observed_on TEXT,                  -- 'YYYY-MM-DD' か 'YYYY-MM'（日が無い出典）か NULL。正規化済み
  survey_year INTEGER, survey_month INTEGER, survey_day INTEGER,
  start_time TEXT, end_time TEXT,    -- 'HH:MM'（forest/shorebird）。mammal の photo_time は start_time に
  season_ja TEXT,                    -- season_ja / survey_period_ja / cycle_ja を出典ごとに
  survey_round TEXT,                 -- rep_no（調査回）
  section_ja TEXT,                   -- section_name_ja / point_ja（ライン区間・ポイント）
  species_ja TEXT, scientific_name TEXT,
  individual_count REAL,             -- 数値化できたときだけ。0 も 0 のまま
  individual_count_raw TEXT,         -- 原文（空・'－'・'-' を含む）
  count_qualifier TEXT,              -- plusminus（'+'/'±'）
  id_note_ja TEXT,                   -- id_confidence_ja（'sp.'/'?'）/ id_type_ja
  out_of_range INTEGER, out_of_time INTEGER,   -- 0/1。元の列がある出典（satochi_bird・satochi_butterfly）だけ（空なら 0）。他は NULL
  taxon_id TEXT,                     -- 名寄せ表の結果（無ければ NULL）
  taxon_resolution TEXT,             -- 'map_sci'/'map_ja'/'unresolved'/'non_taxon'
  in_occurrence INTEGER NOT NULL,    -- 1=occurrence に流す、0=流さない
  exclude_reason TEXT,               -- in_occurrence=0 の理由（下の語彙）
  extra_json TEXT                    -- 出典固有の残りの列（id_visual/song/call・age_class・breeding・weather・subspecies・survey_method・site_type・habitat・municipality・species_en・survey_year_raw 等）
);
CREATE INDEX IF NOT EXISTS ix_moni_src ON moni1000_counts(source_id, survey_year);
CREATE INDEX IF NOT EXISTS ix_moni_sp ON moni1000_counts(species_ja);
```

`exclude_reason` の語彙（機械的に決まるもの）: `zero_count`（個体数 0。不在記録）/ `unresolved_taxon`（名寄せ不能、`sp.` 等）/ `non_wild`（ヒト・ネコ・ウコッケイ）/ `non_species`（科・類・同定不能）。
各理由の件数は §3.4 で manifest の `evidence` に実測を書く。**生の表の行は 1 行も落とさない**（in_occurrence=0 は occurrence にだけ流さない）。

## 3. occurrence への流し方

### 3.1 manifest 5 本・adapter 5 本

`manifests/moni1000_{satochi_bird,satochi_butterfly,forest_bird,satochi_mammal,coast_shorebird}.yml` と `scripts/adapters/` の同名 5 モジュール。
**manifest は出典 1 つにつき 1 本が必須**（`source` が `source_registry.source_id` に一致する規約。出現の `source_id` はここで決まる）。
入力表は 5 本とも `input: {table: moni1000_counts}`。manifest に WHERE は無いので、adapter が `r["source_id"] == SOURCE and r["in_occurrence"] == 1` で絞る（adapter は `ingest.api` 以外を import できない〔`boundary.py`〕ので、共有の補助モジュールは作らず、各 adapter は 20 行程度で重複させる）。
共通項: `region: jp-14`、`target: occurrence`、`update_mode: snapshot`（m10 が全件を置き換えるため）、`edition` は付けない（既存の kuma と同じ）。

adapter が返す行（`occurrence_row`）:

- `record_key = record_id`、`taxon_id = r["taxon_id"]`、`observed_on_raw = r["observed_on"]`（日なしの出典は `YYYY-MM` → 期間の形 `month`）、`lat/lon = r["lat"]/r["lon"]`、
  `coordinate_uncertainty_m`（原本の列をそのまま写す。m10 が `10^(5-coord_decimals)` m で計算。座標が無ければ NULL）、`scientific_name`、`vernacular_name = species_ja`。
- `attributes`: `survey_id`・`site_key`・`site_name_ja`・`place_id`・`season_ja`・`survey_round`・`section_ja`・`individual_count`・`individual_count_raw`・`count_qualifier`・`id_note_ja`・`out_of_range`・`out_of_time`・`start_time`。個体数は **attributes に残し、occurrence の n（記録数）には使わない**（ADR-0025。kuma・eDNA と同じ）。

### 3.2 occurrence に入れる行・入れない行（黙って落とさない）

| 状況 | 扱い |
|---|---|
| 個体数 0（18 行: 鳥 16・蝶 2） | **入れない**（`zero_count`。不在記録を出現にしない） |
| `plusminus` `+`/`±`、個体数が空・`－`・`-`（forest 299 行） | **入れる**（出現は確か。個体数は `individual_count_raw` と `count_qualifier` に残る） |
| `out_of_range`（範囲外区間 919）/ `out_of_time`（516） | **入れる**。attributes に `out_of_range`/`out_of_time` を載せて利用側が除けるようにする（調査の標準区間・時間の外でも種が居たこと自体は事実） |
| `id_confidence_ja` `sp.`（92）/ `?`（53） | 種名が名寄せできれば**入れる**（`id_note_ja` に残す）。名寄せできなければ `unresolved_taxon` |
| 名寄せ不能（`sp.1`、科・類、同定不能、登録に無い和名） | **入れない**（`unresolved_taxon`/`non_species`）。生の表にはある |
| ヒト・ネコ・ウコッケイ | **入れない**（`non_wild`） |
| 日付が欠ける行（mammal の月・日欠 約 2.5%、他は無し） | **入れる**。`observed_on` を補わない（`YYYY` または NULL。期間の形は宣言値に反映） |

この表の行数は m10 の出力と manifest の `evidence` に実測で書き、`expected_row_count` と一致させる（実装担当が m10 実行後に埋める。推定: 鳥 約 17.7k・蝶 約 14.1k・森林鳥 約 8.4k・哺乳類 約 0.5k〜0.6k・シギ 約 0.6k）。

### 3.3 checks

`not_null: [record_key, taxon_id]` / `unique: [record_key]` / `row_count_between: [N, N]`（実測固定）/ `in_registry: taxon` / `date_between`: 鳥 `["2008-01-01","2012-12-31"]`、蝶 `["2008-01-01","2014-12-31"]`、森林 `["2005-01-01","2025-12-31"]`、哺乳類 `["2008-01-01","2012-12-31"]`、シギ `["2004-01-01","2025-12-31"]`（年だけ・`YYYY-MM` の値は、桁数に境界を切って比べる）。

### 3.4 expected（宣言値の決め方）
