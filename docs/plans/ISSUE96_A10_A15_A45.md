# Issue #96 奄美の A10・A15・A45 を protected_areas に入れる

決定済み（Issue #96 オーナー決定 2026-10-11）: 奄美の A10（61）・A15（20）・A45（940）の3つだけ。神奈川の A10・A15・A45 は入れない。
地図は #105。この PR は D1 の表と `get_records(record_set=protected_areas)` まで。流域は PR #107 の DEM 71面。
前例は PR #104（`docs/plans/AMAMI_STEP3C.md`、`load_hazard_zones`）。

## 0. 実測で分かったこと（設計の前提）
- **A45 の `subcompartment_id` は主キーにならない**。940行に対して distinct 784（重複 112 ID、最大8行）。`source_ref`（`...#A45-19_46:712` の末尾 = shp レコード番号）は940行で一意。
- **A10 の `area_size_ha` は ha ではない**。layer 11 では測地面積（`area_km2`×100 ha）の約100倍の値、layer 12・13 は 0.0。使えない。測地面積 `area_km2` だけが全行にある（欠損0）。
- **A10 の 3 レイヤは入れ子**: 11 自然公園地域 21,735 ha ⊃ 12 特別地域 4,347 ha ⊃ 13 特別保護地区 169 ha（`area_km2`×100 の合計）。足し合わせると二重計上。`object_name_ja` は61行とも空。`municipality_names_ja` は空の行が多い。
- **A15 は 2009 年版（A15-09）**。`cancel_date`（指定期間の満了日）が 2009〜2018 のものが19件で、現時点では満了済み（湯湾岳3行だけ 2025-10-31 満了）。「特別保護地区」の湯湾岳1行は同名の「鳥獣保護区」2行と別行（面積が別）。`feature_id` は20件とも一意、`name_ja` 欠損0。
- **A45 は 2018 年度版（A45-19）**。市町村は奄美市376・瀬戸内町317・宇検村245・大和村2。`area_ha_source`（原データの面積、合計 5,444 ha）と測地面積（`area_km2`×100 の合計 4,096 ha）が約25%ずれる。
- `protected_areas` に `region_id` 列は無い。地域は `source_id` の接頭辞から引く（`regions.region_of_source_id`、hazard_zones も同じ）。神奈川の既存行は `source_id` が `kanagawa_*`・`hiratsuka_*`・`hadano_*`。
- 既存の `protected_areas` に geometry 列は無い（点だけ）。`/api/geo/protected-areas` は lat/lon を点で返す。
- c32/c33/c35 の CSV は gitignore 済み（`data/processed`）。m05 は CSV の `watershed_id` を読まず、`Watersheds.find(lon, lat)`（= `load_watersheds()`、DEM 71 面）で埋める。それでも決定どおり c32/c33/c35 を `--region jp-46` で回し直す（CSV と geojson の整合のため）。

## 1. 表の形（推奨）
`protected_areas` を拡張し、**列を2つ足す**: `geometry_geojson TEXT`（NULL 可）。他の列は既存のまま（`region_id` は足さない。hazard_zones と同じく `source_id` で区別）。

| 列 | A10 | A15 | A45 |
|---|---|---|---|
| area_id（主キー） | `nlni_a10_natparks_amami:<object_id>` | `nlni_a15_wildlife_amami:<feature_id>` | `nlni_a45_forest_amami:<shp レコード番号>`（source_ref の `:` 以降） |
| name_ja | NULL（原データに無い。note に書く） | `name_ja` | `<national_forest_name_ja> <compartment_label_ja>`（例「佐仁川内 201_林班_る」）。林班番号は原文のまま |
| category_ja | `layer_name_ja`（自然公園地域/特別地域/特別保護地区） | `protection_class_ja`（鳥獣保護区/特別保護地区） | `国有林` |
| category_code | `natpark_area` / `natpark_special` / `natpark_special_protection`（layer 11/12/13） | `wildlife_reserve` / `wildlife_special_protection` | `national_forest` |
| municipality_ja | `municipality_names_ja`（空は NULL。補完しない） | NULL（原データに市町村が無い） | `municipality_name_ja` |
| area_ha / area_ha_raw | `area_km2`×100 / NULL（`area_size_ha_raw` は ha でないので持ち込まない。note に理由） | `area_km2`×100 / NULL | `area_km2`×100 / `area_ha_source` |
| designated_on / _raw | NULL / `fiscal_year_raw`（指定年度の原文。`fiscal_year` が付く行のみ） | `designated_date` / 同左 | NULL / NULL |
| lat, lon | geometry の `representative_point`（必ず区域の内側。m05 が shapely で計算） | 同左 | 同左 |
| watershed | `ws.find(lon, lat)` | 同左 | 同左 |
| note_ja | 下記 | 下記 | 下記 |
| source_id / source_ref | 出典 ID / CSV の `source_ref` | 同左 | 同左 |

- **lat/lon は代表点にする**（CSV の `centroid_*` は重心で、A10 の細長い区域では区域の外・海上に落ち「重心が流域界の外」になる。hazard_zones も代表点）。`centroid_*` は使わない。
- **二重計上**: 行は入れ子のまま持つ（原データの構造をそのまま出す）。面積の合算で二重にならないよう、A10 の note_ja に「3レイヤは入れ子（自然公園地域 ⊃ 特別地域 ⊃ 特別保護地区）。category_code をまたいで area_ha を足さない」を全61行に入れる。A15 の湯湾岳は別行のまま。
- **note_ja（出典ごとに1文型）**: A10「国土数値情報 A10-15（2015年版）。名称は原データに無い。原データの面積欄は ha でないため使っていない」、A15「A15-09（2009年版）。指定期間 <designated>〜<cancel_date>」、A45「A45-19（2018年度版）。機能類型: <function_type_ja>、林種: <forest_subtype_ja>。小班IDは複数行に重複する」。
- **地域で範囲が違う注記**: 既存の caveat 機構は観測値の系列に掛かる（`caveat_scope` の vocabulary に record_set 相当が無い）ので使わない。`access.yaml` の `basis`（`describe_catalog what='sources'` に出る）に「奄美のみ。神奈川は A10・A15・A45 を取り込んでいない（神奈川の区域は県の別出典 `kanagawa_natural_parks` 等）」を書く。note_ja にも A10・A15 の各行に同じ1文を足さず、basis だけにする（重複を避ける）。
- **geometry**: `geometry_geojson`（6桁、単純化なし。hazard_zones と同じ。合計 約7 MB: A10 1.5・A15 0.15・A45 5.2 MB）を持たせる。#105 が `get_records(include_geometry)` か地図 API で読める。理由: 表と別の置き場（`public/geo` の静的ファイル等）を作ると鮮度判定・シード・サンプルが増える。神奈川の既存行は NULL のまま。単純化が必要になれば #105 が表示時に行う。
  - 影響: `web/src/db/schema.ts` に列追加 → `pnpm run db:generate`（マイグレーション 0023、直接書き換えない）。`web/src/lib/records.ts` の protected_areas に `geometry: "geometry_geojson"` を足し、`include_geometry` の説明文（「植生・河川のみ」）に保護区を足す。`cols` には入れない（一覧に返さない）。`/api/geo/protected-areas` は変えない（点のまま。奄美の点が増えるだけ。`category` で絞れる）。
  - **ID 衝突**: `_assert_no_id_collision`（hazard 前例）で他出典との衝突を止める。`source_id` と CSV の `source_id` の一致も検査する。

## 4. 受け入れ基準（実データ。`sqlite3 'file:data/db/ryuiki.sqlite?mode=ro'`）
```sql
-- 件数と過不足
SELECT source_id, COUNT(*) FROM protected_areas WHERE source_id LIKE 'nlni_a%_amami' GROUP BY 1;
  -- a10=61, a15=20, a45=940
SELECT category_code, COUNT(*) FROM protected_areas WHERE source_id='nlni_a10_natparks_amami' GROUP BY 1;
  -- natpark_area=9, natpark_special=50, natpark_special_protection=2
SELECT category_code, COUNT(*) FROM protected_areas WHERE source_id='nlni_a15_wildlife_amami' GROUP BY 1;
  -- wildlife_reserve=19, wildlife_special_protection=1
-- 神奈川が不変
SELECT COUNT(*) FROM protected_areas WHERE source_id NOT LIKE 'nlni_a%_amami';   -- 728 のまま
-- 主キー・幾何・座標
SELECT COUNT(*) FROM protected_areas WHERE source_id LIKE 'nlni_a%_amami' AND (geometry_geojson IS NULL OR lat IS NULL OR lon IS NULL OR area_ha IS NULL);  -- 0
SELECT COUNT(DISTINCT area_id) FROM protected_areas WHERE source_id LIKE 'nlni_a%_amami';  -- 1021
-- 面積（測地面積の合計）
SELECT source_id, ROUND(SUM(area_ha)) FROM protected_areas WHERE source_id LIKE 'nlni_a%_amami' GROUP BY 1;  -- CSV の area_km2×100 の合計と一致
-- 流域は DEM の ID だけ（旧 W12 の ID が残らない）
SELECT COUNT(*) FROM protected_areas WHERE source_id LIKE 'nlni_a%_amami' AND watershed IS NOT NULL AND watershed NOT LIKE 'dem-amami-%';  -- 0
```
- CSV と照合: 各出典の CSV の行数・`source_ref` の集合が D1 の `source_ref` の集合と一致（EXCEPT 両方向で0）。
- 代表点が区域の内側: 全1021行で shapely の `geom.contains(Point(lon, lat))` が真（テストと原本の両方で）。
- `describe_catalog what='sources'` で3出典の状態が `queryable_via: get_records`、basis に「奄美のみ」が出る。

## 5. メインへの質問
1. **geometry を protected_areas に列で持たせる**（推奨。合計約7 MB、既存の神奈川行は NULL）。代案は、保護区は点だけ持ち #105 が `public/geo` の静的 GeoJSON を使う。後者は表と地図で二重の出力経路になる。どちらにするか。
2. **A45 の相当を `protected_areas` に入れる**（決定どおり）が、国有林の小班は「保護区」ではなく森林の台帳に近い（機能類型・樹種・林齢を持つ）。ここでは区域と面積と機能類型だけ note_ja に入れ、樹種・林齢・保安林区分は捨てる。将来使うなら別表（`forest_subcompartments`）になる。この割り切りでよいか。
3. **A10 の名称が空**（61行とも）。`name_ja` は NULL にして検索で引けない。補えるなら環境省の公園区域名（奄美群島国立公園）を `name_ja` に入れる案があるが、原データに無い値を足すことになる。推奨は NULL のまま。
4. **A15 の満了済み指定**（19/20件）を入れる。2009 年版の指定期間は更新されている可能性が高い。note_ja に指定期間を書くだけで「現在は指定されていない可能性」とは書かない（断定できない）。それでよいか。
5. c32/c33/c35 の取得（zip）がオフラインで足りない場合は、収集の再取得（ネットワーク）を許すか。

## 6. メインの決定（2026-10-11）
1. geometry は `protected_areas.geometry_geojson` 列で持つ（§1 の推奨どおり）。マイグレーション番号は `db:generate` が振る番号に従う（0023 は #106 で使用済みの可能性がある）。
2. A45 は区域・面積・機能類型・林種だけ（§1 どおり）。樹種・林齢・保安林区分は今回捨てる。
3. A10 の `name_ja` は NULL。原データに無い公園名は補わない。
4. A15 の note_ja は指定期間を書くだけ。`access.yaml` の basis には事実として「2009年版。20件中19件は版の時点の指定期間が 2018 年までに満了している」と書く（現在の指定状況は推測しない）。
5. c32/c33/c35 の zip が無ければ再取得してよい（公開データの取得のみ）。
- 既存の `/api/geo/protected-areas` を使う画面に奄美の点が増える場合はそのままにする（地図の作り込みは #105）。担当 B は、どの画面が読んでいるかを確かめて報告する。
