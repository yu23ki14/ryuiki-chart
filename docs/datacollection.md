# 相模川流域データ構造化ループ — プロンプト集

神奈川県・国交省の環境PDFを機械可読データへ構造化するためのプロンプト一式。
役割ごとに**別セッション・別コンテキスト**で動かす前提。

設計の全体像とループ契約の考え方は、同名のドキュメントを参照。

---

## SCHEMA — cells テーブル（正規化ストア）

```text
doc_id           # PDFの識別子（発行元 + 文書名 + 年度）
doc_sha256       # 原本ハッシュ。行政PDFは差し替えが珍しくない
page_no
table_id         # doc内で一意
row_key          # 例: "檜洞丸" / "厚木市" / "2022年度"
col_key          # 多段ヘッダをフラット化: "個体数調整|管理捕獲|メス"
value_raw        # 原文のまま（"2,194" "－" "※1"）
value            # 正規化後（2194）
value_type       # int / float / string / null
unit             # "頭" "頭/km2" "ha" "百万円"
fiscal_year      # 西暦の年度（2022 = 2022-04〜2023-03）
era_raw          # "令和4年度" / "R4" / "2022(令和4)年度"
source_text      # 生テキスト中の該当スニペット（リテラル照合用）
source_bbox      # [x0,y0,x1,y1]
notes_ref        # 該当する注記のID配列
confidence
extractor        # "pdfplumber@0.11" / "yomitoku@0.9" / "vlm:xxx"
verified_by      # "T1,T2" / "human:yuki"
extracted_at
```

## P0 — オントロジー抽出（値は取らない）

**役割**: L0 · 人間レビュー必須

先に語彙だけを集める。値を取らせると語彙抽出が雑になるので、明示的に禁止する。

```text
あなたは日本の行政文書の用語整理を担当します。
添付のPDFから「語彙」だけを抽出してください。数値・実績値は一切抽出しないこと。

抽出する4種類：
1. 区域名・エリア名（例：保護管理区域、生息環境管理エリア、ダム集水域）
   - 本文中にその定義が書かれていれば定義文をそのまま引用する
   - 定義が見つからない場合は definition を null にし、found_definition を false にする
2. 指標名（例：区画法による生息密度、林床植生の植被率、BOD）
   - 単位、測定方法の記述、初出ページを記録する
3. 単位の表記（例：ha, km2, 頭/km2, 百万円, m3/s）
   - 同じ量に複数の単位が使われていればすべて列挙する
4. 年度表記のパターン（例：令和4年度 / R4 / 2022(令和4)年度）
   - 実際に文書内で使われている形をそのまま、出現ページとともに列挙する

出力は以下のJSONのみ。説明文は書かない。
{
  "doc_id": "...",
  "areas":      [{"name":"...","definition":null,"found_definition":false,"pages":[12]}],
  "indicators": [{"name":"...","unit":"...","method":"...","pages":[8]}],
  "units":      [{"literal":"...","quantity":"面積","pages":[3,4]}],
  "era_formats":[{"literal":"R4","pages":[22]}]
}

厳守：
- 推測で定義を補完しない。書いていないことは null。
- 似た名前を勝手に同一視しない。「保護管理区域」と「生息環境管理エリア」は
  別項目として出す。同一性の判断はあなたの仕事ではない。
```

## P1 — 表抽出（Maker）

**役割**: L1 · Maker

1呼び出し＝1表。ページ画像と生テキストの両方を渡し、source_text を必須にすることで後段の照合を可能にする。

```text
あなたは表の抽出だけを行います。解釈・要約・考察は一切しません。

入力：
- [IMAGE] 表を含むページの画像
- [RAW_TEXT] 同じページを pdfplumber で抽出した生テキスト
- [VOCAB] L0で確定した語彙辞書（区域名・指標名・単位）

タスク：
[IMAGE] の表を、1セル1レコードのJSON配列にしてください。

各レコードの必須フィールド：
- row_key      行の見出し。多段なら "上位|下位" で連結
- col_key      列の見出し。多段ヘッダは "上位|中位|下位" で連結
- value_raw    セルの表示文字列をそのまま（"2,194" "－" "n.d." を含む）
- unit         その列/セルの単位。表内に明示がなければ null
- source_text  [RAW_TEXT] 内に literal に存在する部分文字列。
               value_raw を含む、前後を含めた10〜40文字程度を切り出すこと

厳守：
- source_text は [RAW_TEXT] からのコピーであること。1文字でも変えない。
- [RAW_TEXT] に該当箇所が見つからないセルは、value_raw を null にし、
  "unreadable_reason" にその理由を書く。推測して埋めない。
- 結合セルは展開する（結合元の値を各セルに複製し、"merged": true を付ける）。
- 合計行・小計行も除外せず抽出し、"is_total": true を付ける。
- 空欄と 0 と "－" を区別する。空欄は null、"－" は value_raw="－"。
- 表の外にある注記（※印、脚注）は抽出対象外。P4が別途扱う。

出力はJSON配列のみ。
```

## P2 — 検証（Checker）

**役割**: L1 · Checker · 別セッション

Makerの出力と生テキストだけを渡す。ページ画像は渡さない——同じ材料を見た瞬間、独立した検証ではなくなる。判定のみで、修正はさせない。

```text
あなたは検証だけを行います。修正はしません。

入力：
- [EXTRACTED] 抽出結果のJSON配列
- [RAW_TEXT] 同じページの生テキスト

各レコードについて、以下を順に判定してください。

C1: source_text が [RAW_TEXT] に literal に存在するか（完全一致の部分文字列）
C2: value_raw が source_text に含まれているか
C3: value_raw が value_type と整合するか（数値欄に非数値が入っていないか）
C4: unit が [VOCAB] の単位リストに存在するか
C5: is_total=true のレコードについて、同じ col_key を持つ非合計セルの和と
    一致するか（相対誤差 0.5% 以内なら丸めとして許容）
C6: row_key / col_key に、明らかな取り違え（同じ値の重複、連番の飛び）がないか

出力：
{
  "verdict": "pass" | "fail",
  "failures": [
    {"index": 12, "check": "C1", "detail": "source_text が RAW_TEXT に存在しない"}
  ],
  "summary": {"total": 84, "passed": 81, "failed": 3}
}

厳守：
- 判定は [RAW_TEXT] のみを根拠にする。あなたの知識で「たぶんこうだろう」と
  補完しない。
- 1件でも C1 が失敗したら verdict は "fail"。これは幻覚の直接的な証拠なので
  例外を認めない。
- 修正案を書かない。JSONのみを返す。
```

## P3 — 修正（Fixer）

**役割**: L1 · Fixer

失敗したセルだけを渡す。通ったセルを触らせないのが要点。触らせると、直すたびに別の場所が壊れる無限ループに入る。

```text
あなたは指摘されたセルだけを修正します。

入力：
- [FAILURES] P2が返した失敗レコードの配列
- [IMAGE] 元のページ画像
- [RAW_TEXT] 元の生テキスト
- [ATTEMPT] 今回が何回目の修正か（1〜3）

タスク：
[FAILURES] に挙がった index のレコードのみを修正して返してください。

厳守：
- [FAILURES] にない index のレコードは出力に含めない。
- source_text は必ず [RAW_TEXT] からコピーする。
- 読み取れないと判断した場合は、無理に埋めずに
  {"index": 12, "value_raw": null, "unreadable_reason": "..."} を返す。
  これは失敗ではなく、正しい結果です。
- [ATTEMPT] が 3 の場合、前2回と同じ答えを返すことは禁止。
  同じ答えしか出せないなら unreadable_reason を書いて null にすること。

出力は修正後のレコードのJSON配列のみ。
```

## P4 — 注記・比較可能性の抽出

**役割**: L1 · 人間レビュー行き

この案件で一番重要なプロンプト。「単純比較できない」という県自身の警告を拾い損ねると、データセット全体の信頼性が飛ぶ。

```text
あなたは、表の解釈を制約する記述を探します。

入力：ページ本文テキストと、そのページに含まれる表のID一覧

以下の4種類を抽出してください：
1. 脚注・注記（※、注)、＊ などで始まる記述）
2. 調査年・調査対象範囲の但し書き
   （例：「調査年は分類群ごとに異なる」「国管理区間のみ」）
3. 比較可能性への言及
   （例：「気象条件が同一ではないため単純比較はできない」
     「令和3年度から算定方法を変更した」）
4. 定義の変更・読み替えの記述
   （例：「本表の『保護管理区域』は旧計画の『特別区域』を含む」）

出力：
[{
  "note_id": "n_012",
  "table_ids": ["t_003"],
  "kind": "footnote" | "survey_scope" | "comparability" | "definition_change",
  "text": "原文のまま引用",
  "page": 22,
  "blocks_timeseries": true | false,
  "reason": "なぜ時系列比較を妨げる/妨げないと判断したか"
}]

厳守：
- 原文の引用は改変しない。
- blocks_timeseries が true のものは、必ず人間レビューに回されます。
  判断に迷ったら true にすること（偽陰性のほうが有害）。
```

## P5 — 失敗のトリアージ（外側ループ）

**役割**: L2 · 日次

個別の失敗を人間に流すと埋もれる。束ねて原因のクラスタにしてから出す。辞書パッチの提案までさせるが、適用は人間の承認を挟む。

```text
あなたは、抽出パイプラインの失敗ログを分類します。

入力：[FAILURES] 直近24時間の needs_human レコード（複数PDF横断）

タスク：失敗を以下のカテゴリに分類し、件数の多い順に並べてください。
A. 辞書不足   … 未知の区域名・指標名・単位が原因
B. OCR品質    … 文字が潰れている、罫線が読めない、スキャン画質
C. 表構造     … 結合セル、ページ跨ぎ、罫線なし表
D. 定義の曖昧さ … 同名の別概念、注記による読み替え
E. その他

各カテゴリについて：
- 代表例を3件（doc_id, page, 失敗内容）
- 推定原因
- 提案する対処（Aなら辞書に追加すべき語のリスト、Bなら再OCRの推奨設定）

さらに、辞書へのパッチ案を diff 形式で出してください。
ただしこれは提案であり、適用は人間が行います。適用済みとして書かないこと。

出力：Markdown。最後に「人間の判断が必要な項目」を箇条書きで。
```

## P6 — SKILL.md（プロジェクト固有ルール）

**役割**: L0 · 全ループが参照

6要素でいう Skills。ここを書かずに始めると、同じ注意書きを毎回プロンプトに貼ることになり、更新が効かなくなる。

```text
# 神奈川県環境PDF 構造化ルール

## 年度の扱い
- 「令和4年度」= 2022年度 = 2022-04-01 〜 2023-03-31
- 文書内に少なくとも4パターンが混在する。すべてパースできること：
  「平成29年度」「H29年度」「令和元年度」「2006(平成18)年度」
- 同一文書内で本文と表の表記が違う（本文は併記、表は略号）ケースが実在する
- 西暦先出し（"2005(平成17)年"）と元号先出し（"平成19(2007)年度"）が
  文書によって逆になる。順序で判定せず、両方を受け付ける

## 単位
- 面積は ha と km2 が混在する。1 km2 = 100 ha で正規化し、元表記は残す
- 生息密度は「頭/km2」に統一されているが、面積は ha で書かれることがある
- 金額は「百万円」「億円」が混在する。円に正規化し、元表記を残す

## 区域名（同一視は禁止。人間が承認した対応表のみ使う）
- シカ関連：保護管理区域 / 生息環境管理エリア / 定着防止区域
- 水源関連：水源保全地域 / 水源の森林エリア / 地域水源林エリア / ダム集水域
- 河川関連：国土交通大臣管理区間 / 国管理区間 / 直轄管理区間
  → 上記は「似ているが別概念かもしれない」ものとして扱う。
    対応表 areas_mapping.yaml に人間が書いた行がある場合のみ名寄せする

## 河川・水域の別称
- 相模川は山梨県内では「桂川」。同一河川として扱うが、出典の表記は残す

## 禁止事項
- 数値を推測で埋めない
- 表をまたいで値を補完しない
- 注記を要約しない（原文引用のみ）
- 合計が合わないときに、内訳を調整して合わせない（fail として報告する）
```

## P7 — ループ契約（オーケストレータ設定）

**役割**: L1/L2 · 実行制御

停止条件・予算・エスカレーション先を、プロンプトの外にコードとして置く。ここがプロンプト内の自然言語にあると、モデルが自分で緩められる。

```yaml
loop: table_extraction
unit: table               # PDFではなく表を1単位とする

goal:
  all_cells_verified: true
  min_cells: 1
  require_source_text: true
  require_bbox: true

budget:
  max_turns: 8
  max_minutes: 10
  max_tokens: 120000

stop:
  consecutive_failures: 3   # → needs_human、PDFは続行
  on_hallucination: abort   # C1失敗は即時隔離
  on_unknown_vocab: pause   # 未知の区域名 → L2のトリアージへ

roles:
  maker:   {prompt: P1, sees: [image, raw_text, vocab]}
  checker: {prompt: P2, sees: [extracted, raw_text, vocab], new_session: true}
  fixer:   {prompt: P3, sees: [failures, image, raw_text]}

escalation:
  to: "#env-data レビュー担当"
  payload: [doc_id, page, table_id, failures, page_image, raw_text]

idempotency:
  key: [doc_sha256, page_no, table_id, extractor_version, vocab_version]
  # 辞書を更新したら vocab_version が変わり、全件が再実行対象になる
```
