# zone（Ridge to Reef 1–5）の操作的定義

**これは我々（データ統合作業）が便宜的に定めた操作的な区分であり、公式の行政区分・学術区分ではない。**
要求定義書（`app_description.md` §6）は観測地点に「ゾーン（Ridge to Reef 1–5）」を持たせることを
求めているが、この区分に対応する公開データは存在しない。そのため、以下の通り標高と海岸線からの
距離という機械的に算出可能な指標だけを用いて、暫定的に 1〜5 の値を割り当てている。

**重要な限界**:
- 分水嶺・尾根線・行政界などの地形学的な厳密な流域構造は考慮していない。
- 標高・海岸距離のしきい値は本作業で仮に置いた値であり、水野研レビュー等で確定する必要がある
  （`app_description.md` の確定度「仮」に対応）。
- `sites.zone` にこの値が入っている地点は、すべてこの操作的定義に基づくものであり、
  現地調査や専門家によるゾーニングの結果ではない。

## 定義

| zone | 名称（仮称） | 条件 |
|---|---|---|
| 1 | 山地源流域 | 標高 > 800m |
| 2 | 山地渓流 | 400m < 標高 ≤ 800m |
| 3 | 丘陵・扇状地 | 100m < 標高 ≤ 400m |
| 4 | 平野・沖積低地 | 標高 ≤ 100m、かつ海岸線から2kmより遠い |
| 5 | 河口・沿岸 | 標高 ≤ 100m、かつ海岸線から2km以内 |

標高が取得できなかった地点（`elevation_m IS NULL`）は `zone` も NULL のままにする（推測しない）。

## 標高の取得方法

- 気象庁アメダス地点: 気象庁が公表している観測点の標高値（自己申告値）をそのまま使用。
- それ以外（環境省 公共用水域水質測定点・ダム・相模川ライブカメラ・モニタリングサイト1000）:
  国土地理院 標高API（`https://cyberjapandata2.gsi.go.jp/general/dem/scripts/getelevation.php`）を
  1地点あたり1.5秒スロットルで呼び出して取得。API呼び出し件数の上限は
  `scripts/m01_sites.py` の `ELEV_CAP`（500件）で、対象地点数（約374件）はこの上限内に収まっている。
  API呼び出し結果は `data/processed/_elevation_cache.json` にキャッシュし、再実行時の
  重複呼び出しを避けている。

## 海岸線からの距離

神奈川県の海岸線（東京湾岸〜三浦半島〜相模湾岸）を20点程度の折れ線で近似した「粗い海岸線」
（`scripts/m01_sites.py` の `COASTLINE_LONLAT`）に対する最短距離（メートル、緯度による経度方向の
局所補正のみを行った簡易平面近似）を用いている。行政が公開する正式な海岸線ポリゴンではなく、
主要地名の座標を手動で結んだ近似であることに注意。

## `treatment`（対策区／対照区／参照）との違い

`treatment` は zone とは別の概念であり、公開データには一切存在しないため、実データ由来の
`sites` レコードでは常に NULL のままにしている。合成（デモ用）データを別途生成する場合に限り、
そちらで付与する想定。
