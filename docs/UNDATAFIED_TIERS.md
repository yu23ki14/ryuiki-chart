**実際にURLを叩いて**中身・件数・ライセンスを確認して分類した。調査は読み取り専用で、

## 判定で分かった重要な事実

### 1. 「取込済み」に見えて実は空だったソースが12件あった
`source_registry` にURLは登録されているが `record_count=0` ——
前任者が取りに行って諦めた記録だけが残っている状態のものが12件あった。
これを「済」に数えると未データ化を12件見落とす。全件を再検証した結果、
**うち3件は断念判断そのものが誤り**だった（下記）。

### 2. 前任者の「取得不能」判断3件が実測で覆った

| 行 | ソース | 当時の記録 | 再検証の結果 |
|---:|---|---|---|
| 108 | 自然環境調査Web-GIS | 「動的タイル配信で抽出困難」 | 登録URLはDNS消滅済み。後継のArcGISアプリに**認証不要のREST Feature Server が28本**。神奈川範囲で植生ポリゴン13,206件・タヌキ分布メッシュ209件の取得を実確認 → **Tier 1** |
| 109 | いきものログ | 「SPAのセッション状態の再現が必要」 | `POST /life2/search` は認証もセッションも不要のステートレスJSON API。`ken_code=14` で**神奈川151,108件**、ページング動作確認 → **Tier 2** |
| 194 | 平塚市 大気環境 | 「範囲外と判断」 | `download/{年}_{局}.csv` の直リンク65本。当時の見送りは技術的障害ではなく重複回避の判断 → 技術難易度としては **Tier 1** |

これは**登録した文書の本数**であって行数ではない。実際には `cells.sqlite` に

### 4. CSVのリンク自体が古い
実地確認の過程で、リンク切れ・移転が多数見つかった。主なもの:

- 行110/111 植生図: `gis.biodic.go.jp` は **NXDOMAIN**。後継はG空間情報センターの
  GeoPackage直リンク（関東ブロック約673MB、ログイン不要、PDL1.0）
- 行80 河川環境データベース: `www5.river.go.jp` も名前解決不可

- 行166 秦野の地下水ダッシュボード: CMS移行で404

- `scripts/c01_ckan.py` の `bodik_kanagawa` エントリ（`odcs.bodik.jp/kanagawa`）も
  404。実APIは `data.bodik.jp`

### 5. 既存レジストリより厳しい可能性のあるライセンス表記（要確認）
`agri-kanagawa.jp`（ブナ衰退WEB版 `buna_suitai_web` の取得元）は、フッターが素の
"All rights reserved" で、サイトポリシーのページが見つからなかった。
既存レジストリは「政府標準利用規約(第2.0版)相当（要確認）」と記録しているが、
**この記録より実際は厳しい可能性がある**。配布前に確認すること。

### 収集して分かった、当初の想定と違ったこと

- **前任者の「取得不能」判断3件はやはり誤りだった。** 環境省 ArcGIS は認証不要で
  植生13,206ポリゴンが実際に取れた。平塚市大気も直リンクCSV 65本で全量取れた。
- **ツキノワグマPDFは5本すべてのヘッダに年度に関わらず「（速報値）」と印字されている。**
  PDF本文だけでは確定値か速報値かを判別できないので、入口HTMLのリンク文言に書かれた
  集計期間（「3月末まで」で終わっているか）から機械的に判定している。
- **平塚市大気には公式文書に無い欠測センチネル `-999` がある。**
  公式仕様は「欠測=9999、未測定=9998」だが、2015年度・大野公民館の 2016-03-01 12時の
  NOx と THC の2セルだけに `-999` が出る。無関係な2項目が同一時刻に揃って同じ値を取るのは
  実測としてあり得ないため欠測として扱っている。一方、気温の負値は複数局で冬季に相関するため
  実測として残している。
- **地盤沈下の表3（市町別最大沈下量 累計）は構造化していない。**「調査開始以来」というラベルの
  列が2つあり、結合セルの配置だけでは区別を確認できなかったため、推測で割り当てていない。
- **横浜市の河川水位は5分間隔で1,083万行（CSV 2.4GB / JSONL 3.9GB）あった。** 相模川水系ではない
  隣接下流都市の参考データなので、日平均・日最高に畳んで投入している。
  容量が過大なため処理済み CSV/JSONL は削除した（2026-08-30）。月次の原本は
  `data/raw/yokohama_river_waterlevel/`（25本・521MB）に残してあるので、
  `scripts/c86_ckan_bodik_yokohama.py` を流せばネットワークに出ずに作り直せる。
- CSVのリンク切れ・記載違いを実地で複数修正した（特別緑地保全地区と近郊緑地保全区域の
  PDFファイル名が入れ替わっていた、平塚の公園CSVは294件ではなく290件 等）。
