# ADR-0009: 定量下限未満を 0 で表さず、検閲を明示的に持つ

- 状態: 提案中 / 日付: 2026-09-06
- 関連: ADR-0007（observation）, ADR-0011（キューブ）, ADR-0013（caveat）, ADR-0014（応答）,
  ADR-0021（キューブの鍵）

**2026-09-24 追記（実装。ADR-0016 Phase B「ファクトとキューブ」で `imputation='zero'`
のみ実装したのに続く最初の意図的な変更）**: 決定2・決定4を実装した。要点は決定2・決定4
それぞれの本文に追記した。実装は `scripts/b04_build_cube.py`（`observation_agg`
の `value_zero`/`value_lod` 列）・`scripts/migrate/censoring.py`（`ZERO_IMPUTED_CENSORING`
等の唯一の定義）。実測: `observation_agg` 2,022,964セル（変化なし。決定4のとおり
セル数は増えない）、`value_lod` が `value_zero` と食い違うセル 241,063、
`value_lod IS NULL`（`n_not_detected = n` の格）3,201。

**注記（`registry/caveat.yaml` の `censored`）はオーナー判断で `zero` 系列を
名指しする文面にした**（「この画面の値は定量下限未満を 0 とみなして集計している」）。
「代入方式によって変わる」のような系列に依らない書き方も検討したが、
いま画面（v1 派生表経由）が実際に読んでいるのは `zero` 系列だけなので、
系列に依らない書き方にすると読者が自分の見ている値がどちらか分からないまま
になる——**いま見えているものを名指しする方が正直**、という判断。
**申し送り**: `lod` 系列を画面・応答封筒（ADR-0014）に出す最初の消費者が
現れたら、この本文を系列に依らない書き方（または系列ごとに動的に差し替える
書き方）に変えること。

**2026-09-25 追記（/code-review 対応。実装の機械検証3件のうち2件が誤っていた）**:

1. **検証1（`(value_lod IS NULL) = (n_not_detected = n)`）は「葉の格」
   （`observation` から直接作る格）でしか単位が揃わない。** 月次・年次を
   日次セルから積み上げる格では、`n` は寄与した**日次セルの個数**、
   `n_not_detected` はその日次セルたちの `n_not_detected`（観測行の個数）の
   **和**で単位が違う——`n_not_detected = n` という等式は本来比較できない
   2つの量を比べていた。実データでこの等式が通っていたのは「ND がすべて
   `fiscal_year` の出典配布行に限られ、日次の積み上げに一切乗らない」という
   **現データの性質**のおかげであり、本 ADR・実装指示が禁じた依存そのもの
   だった。積み上げの格には、単位を混ぜない片方向の含意
   （`n_not_detected=0 ⇒ value_lod IS NOT NULL`）だけを課すように直した。
   実装は `scripts/b04_build_cube.py` の `_CHECK1_VIOLATION_SQL`。
2. **検証3（`value_lod >= value_zero`）は「値は非負」という宣言していない
   前提に乗っていた。** not_detected は zero 側で0・lod 側で除外なので、
   実測値が負の変数（河川水位・地下水位・気温・流量・PM2.5 等、実データで
   75,871セルが負値を含む）だと、ND を含むセルでは不等式が逆転しうる
   （具体例: 値が `[-10.0, ND]` のセルは zero 側平均 `-5.0`・lod 側平均
   `-10.0` で `value_lod < value_zero`）。**`n_not_detected = 0` のセルに
   限って不等式を課す**ように直した——below_lod だけを含むセルは、
   `censoring_limit` が正である限り、他のメンバーの符号によらず
   `value_lod >= value_zero` が成り立つ（below_lod の行は zero 側で0・
   lod 側で正の値に置き換わるだけで、他のメンバーの寄与は両系列で同一の
   ため）。ND を含むセルは「0で埋める」（zero）と「その行ごと除外する」
   （lod）で分母・分子の構成そのものが変わるため、この論法が成り立たない。
   実装は `_CHECK3_VIOLATION_SQL`。
3. **入力検証を1つ追加した**: `censoring='below_lod' AND censoring_limit IS
   NULL` の行があると、`value_lod` の代入が計算できず黙って非メンバー
   扱いになる（3つの機械検証すべてをすり抜ける）。b03 は必ず埋めるため
   実データでは起きないが、`_assert_below_lod_has_censoring_limit`
   （`observation` に対する入力側の検証）を `build_cube()` の先頭に足した。
4. 決定4-4の導出式（`half_lod`・検閲除外平均）の成り立つ範囲を訂正した
   （下記決定4参照）。

## 背景（実測）

`measurements` 323,164行のうち、

```
value_raw が '<' で始まる行         : 75,689  (23.4%)   -- 定量下限未満
そのうち value に入っている値       : すべて 0.0
value_raw = 'ND' の行               :  1,067            -- 不検出。value は 0.0
value = 0 の行の総数                : 76,909
そのうち本当の 0（value_raw が '0'/'0.0'/'0.00'）:  153
```

つまり **`value=0` の 99.8% は「0 が観測された」ではない**（検閲 75,689 ＋ 不検出 1,067）。
本当の 0 は **153行だけ**。**列だけを見て両者を区別できない。**
`ND` は**限界値を持たない不検出**なので、`<0.5` とは扱いを変える必要がある。

区別の手がかりになりそうな `detection_flag` は機能していない。

```
detection_flag  value=0の数 / 全体      解釈
'0'             64,756 / 258,164        出典側のコードがそのまま漏れている
NULL             9,220 /  47,800
'1'                  3 /  13,976
'10'             1,825 /   2,052
'30'               896 /     938
'20'               209 /     221
'<'                  - /      12        ← 検閲を意味しそうな値はわずか12行
'11'                 0 /       1
```

現在この事実は `web/src/lib/domain.ts` の `DATA_CAVEATS.censored` に日本語の注記として
書かれており、画面では中抜きの点で描いている。一方、集計を作る
`web/scripts/build-derived.mjs` は `AVG(value)` で**検閲行の 0 を平均に含めている**。
つまり現行の全平均値は下方に偏っている。**MCP クライアントはこの注記を読めない。**
このまま公開すると「BOD が 0 mg/L の地点が7万件ある」という分析が出る。

## 決定

**検閲を値の一級属性として持ち、検閲値の `value_num` に 0 を入れない。**

```
censoring        'none' | 'below_lod' | 'above_lod' | 'not_detected' | 'trace' | 'unknown'
censoring_limit  検出/定量限界の数値（'<0.5' なら 0.5）
value_num        censoring='none' のときのみ意味を持つ。検閲時は NULL
value_raw        原表記（'<0.5'）を必ず残す
```

1. **検閲行の `value_num` は NULL**。0 を入れない。`0` は「0 が観測された」の意味に戻す。
2. **`value_raw='ND'` は `censoring='not_detected'`、`censoring_limit=NULL`。**
   限界値が無いので half_lod のような代入は計算できない。
   集計では **`n_not_detected` として別に数え、平均には含めない**（含めるなら
   `imputation` の指定が必要）。

   **2026-09-24 追記（実装。`zero`/`lod` で非対称）**: `not_detected` の扱いは
   系列によって非対称にする。
   - `value_zero`: 0 として平均に含める（**v1 の再現のため**——v1 は
     `value=0.0` の ND 行を `AVG`/`COUNT` に含めている。ADR-0016 の受け入れ
     基準「`imputation='zero'` で v1 の値を誤差0で再現する」を満たすには、
     ここだけは本節の本来の規定（代入しない）から外れる）。
   - `value_lod`: 本節の規定どおり、限界値が無いので**代入せず、平均から
     除外する**。
   - 実装（`scripts/b04_build_cube.py`）は「ND だけの格では `AVG` が NULL を
     返す」という一般形（`CASE WHEN censoring='not_detected' THEN NULL ELSE
     ... END` を `AVG`/`MIN`/`MAX` に渡すだけ）で書き、**「ND を含むセルは
     すべて100% ND」という実データの性質には依存しない**（この性質は機械
     検証にだけ使う。決定4の「機械検証」参照）。
3. **`detection_flag` は捨てない**。出典コードとして `source_flag_raw` に退避し、
   意味が判明した出典についてのみ `censoring` へのマッピングをマニフェストに書く。
   意味が不明なものは `censoring='unknown'` とし、**推測でマッピングしない**。
   ただし `'10'`（value=0 率 89%）`'20'`（95%）`'30'`（96%）は検閲コードの疑いが濃いので、
   **出典に当たって確認する**タスクとして残す（`needs_review`）。確認できるまで
   `unknown` のままにし、`n_censored` に混ぜない。
4. **代入方法に既定値を置かない。** `imputation` はキューブのキーであり、
   集計を要求する側が明示する必須パラメータとする（`none` / `zero` / `half_lod` / `lod`）。
   `half_lod` は環境分析でよく使われるが、LOD が年代・検査機関で変わると系列に段差が出るため、
   「妥当な既定」として黙って適用してよいものではない。
   応答は原則として **`lod` と `zero` の両方（上限と下限）を併記**し、
   単一値が必要な場合のみ利用側が方式を選ぶ。

   **2026-09-24 追記（実装。併記は列で持つ）**: `imputation` は**論理的な軸**
   （クエリのパラメータ）だが、`observation_agg`（ADR-0011 のキューブ）では
   **次元キーではなく列**として持つ（`value_zero`/`value_lod` の2列。
   `imputation ∈ {zero, lod}` は次元キーから外れ、12列になった。詳細は
   ADR-0011・ADR-0021 の追記）。理由:
   1. `imputation` は同じセルのメンバーを分割しない——`zero`/`lod` の2系列は
      `n`/`n_censored`/`n_not_detected`/`n_places` が同一で、変わるのは
      代入する値だけ。次元キーに残すと「同じメンバーのセルが2行に分かれる」
      という誤ったモデルになる。
   2. 全セル二重化（次元キーに残したまま `imputation` の値を増やす）は
      +462MB 相当、列を2本足す方式は +16MB 程度で済む見込みだった（設計時の
      試算）。実装後の実測では `observation_agg`（dbstat）は 444.4MB
      （旧: 461.9MB）と、むしろ**減った**——13列目（`imputation`、常に
      `'zero'` の TEXT 列）を1本消した分が、`value_lod` 列（REAL、うち
      3,201セルは NULL）を1本足した分を上回った。
   3. 列にすることで「`lod` で引いたのに無い」が構造的に起きない（`zero`/
      `lod` は常に同じ行の2列として一緒に存在する）。
   4. `half_lod` の平均や「検閲を除外した平均」は**保存せず、式で導出する**
      ——ただし**どちらも成り立つ範囲が限られる**（/code-review 指摘6。
      2026-09-25 訂正: 初版の式はこの範囲を書いておらず、積み上げの格
      〔月次・年次を日次セルから作る側〕では分母が負になる／0除算になる
      箇所があった）。
      - `half_lod` の平均 = `(value_zero + value_lod) / 2`
        **（`n_not_detected = 0` のセルに限る）**。below_lod だけを含む
        セルは、zero 側・lod 側どちらもメンバーの集合（`n`）と分母が同一で、
        censoring_limit を挟んだ内分点を取るだけなので、この式は**葉の格・
        積み上げの格どちらでも成り立つ**（積み上げの格は「日ごとの
        `(value_zero+value_lod)/2` の平均」＝「積み上げ後の
        `(value_zero+value_lod)/2`」——平均の線形性による）。
      - 検閲を除外した平均（below_lod・not_detected の両方を除く）
        = `value_zero × n / (n − n_censored − n_not_detected)`
        **（葉の格に限る。`n − n_censored − n_not_detected > 0` が必要）**。
        `value_zero` は below_lod/not_detected を 0 として計算した平均なので、
        `× n` で合計に戻し、検閲行の数を引いた件数で割り直せば「検閲行を
        除いた平均」になる——ただしこの `n` は**観測行の個数**でなければ
        ならない。積み上げの格（月次・年次を日次セルから作る側）の `n` は
        **日次セルの個数**、`n_censored`/`n_not_detected` は日次セルの値の
        **和**（観測行の個数）なので単位が違い、この式をそのまま当てはめると
        分母が負になる、あるいは意味の無い値になる（/code-review 指摘6）。
      - **`n_not_detected > 0` の積み上げの格では、上記どちらの式も成り立たない
        ——`value_lod` 側で実際に平均に入ったメンバー数（日次セルのうち
        全部 ND でなかったものの個数、または観測行ベースの実メンバー数）を
        `observation_agg` は持っていないため、既存の列だけからは復元できない**
        （何が足りないかを正直に書く。将来この式を使う消費者が必要とするなら、
        その列を足すところから始める）。
   5. ADR-0023 の正準単位も同じ形（列）で並存できるので、キューブを二度
      作り直さずに済む。
   却下した案は決定4本文のとおり（全セル二重化・差の出るセルだけ持つ案）。
   実装・機械検証・実測件数は `scripts/b04_build_cube.py` のモジュール
   docstring「機械検証」節参照。
5. **応答には常に `censoring` / `n_censored` / `n_not_detected` / `imputation` を含める**（ADR-0014）。

## 影響

- **良い**: 公開データを読んだ第三者が誤った結論を出す最大の経路が塞がる。
  平均値の計算方法が明示され、比較可能性が上がる。`domain.ts` の注記がデータに載る。
- **コスト**: `value_num` が NULL になるため、素朴な `avg(value)` が検閲行を無視するようになる
  （現行は 0 として平均を押し下げていた）。**既存の全グラフの数値が変わる。**
  変化の方向と大きさを移行時に記録し、画面の注記を更新する必要がある。
- **注意**: 代入方法を変えると時系列が変わるので、`imputation` はキューブの
  キーの一部として持ち、複数方式を並存させられるようにする。

## 検討した代替案

- **`value=0` のまま `is_censored` フラグを足す**: 移行は軽いが、フラグを見ない利用者が
  必ず出る。公開・MCP 前提では「見なくても間違えない」設計を優先する。却下。
- **検閲値を除外する**: 単純だが、23.4% を捨てることになり「検出されなかった」という
  情報も失う（低濃度であることは重要な情報）。却下。
- **代入済みの値だけを配る**: 利用は楽だが、代入方法を利用者が選べず再現性も落ちる。
  代入は L3 の集計時に、方法を明示して行う。却下。
