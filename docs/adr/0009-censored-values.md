# ADR-0009: 定量下限未満を 0 で表さず、検閲を明示的に持つ

- 状態: 提案中 / 日付: 2026-09-06
- 関連: ADR-0007（observation）, ADR-0013（caveat）, ADR-0014（応答）

## 背景（実測）

`measurements` 323,164行のうち、

```
value_raw が '<' で始まる行         : 75,689  (23.4%)   -- 定量下限未満
そのうち value に入っている値       : すべて 0.0
value_raw = 'ND' の行               :  1,067            -- 不検出。value は 0.0
value = 0 の行の総数                : 76,909
そのうち本当の 0（value_raw が '0'/'0.0'/'0.00'）:  153
```

つまり **`value=0` の 99.8% は「0 が観測された」ではない**（検閲 75,689 ＋ 不検出 1,067）。
本当の 0 は **153行だけ**。**列だけを見て両者を区別できない。**
`ND` は**限界値を持たない不検出**なので、`<0.5` とは扱いを変える必要がある。

区別の手がかりになりそうな `detection_flag` は機能していない。

```
detection_flag  value=0の数 / 全体      解釈
'0'             64,756 / 258,164        出典側のコードがそのまま漏れている
NULL             9,220 /  47,800
'1'                  3 /  13,976
'10'             1,825 /   2,052
'30'               896 /     938
'20'               209 /     221
'<'                  - /      12        ← 検閲を意味しそうな値はわずか12行
'11'                 0 /       1
```

現在この事実は `web/src/lib/domain.ts` の `DATA_CAVEATS.censored` に日本語の注記として
書かれており、画面では中抜きの点で描いている。一方、集計を作る
`web/scripts/build-derived.mjs` は `AVG(value)` で**検閲行の 0 を平均に含めている**。
つまり現行の全平均値は下方に偏っている。**MCP クライアントはこの注記を読めない。**
このまま公開すると「BOD が 0 mg/L の地点が7万件ある」という分析が出る。

## 決定

**検閲を値の一級属性として持ち、検閲値の `value_num` に 0 を入れない。**

```
censoring        'none' | 'below_lod' | 'above_lod' | 'not_detected' | 'trace' | 'unknown'
censoring_limit  検出/定量限界の数値（'<0.5' なら 0.5）
value_num        censoring='none' のときのみ意味を持つ。検閲時は NULL
value_raw        原表記（'<0.5'）を必ず残す
```

1. **検閲行の `value_num` は NULL**。0 を入れない。`0` は「0 が観測された」の意味に戻す。
2. **`value_raw='ND'` は `censoring='not_detected'`、`censoring_limit=NULL`。**
   限界値が無いので half_lod のような代入は計算できない。
   集計では **`n_not_detected` として別に数え、平均には含めない**（含めるなら
   `imputation` の指定が必要）。
3. **`detection_flag` は捨てない**。出典コードとして `source_flag_raw` に退避し、
   意味が判明した出典についてのみ `censoring` へのマッピングをマニフェストに書く。
   意味が不明なものは `censoring='unknown'` とし、**推測でマッピングしない**。
   ただし `'10'`（value=0 率 89%）`'20'`（95%）`'30'`（96%）は検閲コードの疑いが濃いので、
   **出典に当たって確認する**タスクとして残す（`needs_review`）。確認できるまで
   `unknown` のままにし、`n_censored` に混ぜない。
4. **代入方法に既定値を置かない。** `imputation` はキューブのキーであり、
   集計を要求する側が明示する必須パラメータとする（`none` / `zero` / `half_lod` / `lod`）。
   `half_lod` は環境分析でよく使われるが、LOD が年代・検査機関で変わると系列に段差が出るため、
   「妥当な既定」として黙って適用してよいものではない。
   応答は原則として **`lod` と `zero` の両方（上限と下限）を併記**し、
   単一値が必要な場合のみ利用側が方式を選ぶ。
5. **応答には常に `censoring` / `n_censored` / `n_not_detected` / `imputation` を含める**（ADR-0014）。

## 影響

- **良い**: 公開データを読んだ第三者が誤った結論を出す最大の経路が塞がる。
  平均値の計算方法が明示され、比較可能性が上がる。`domain.ts` の注記がデータに載る。
- **コスト**: `value_num` が NULL になるため、素朴な `avg(value)` が検閲行を無視するようになる
  （現行は 0 として平均を押し下げていた）。**既存の全グラフの数値が変わる。**
  変化の方向と大きさを移行時に記録し、画面の注記を更新する必要がある。
- **注意**: 代入方法を変えると時系列が変わるので、`imputation` はキューブの
  キーの一部として持ち、複数方式を並存させられるようにする。

## 検討した代替案

- **`value=0` のまま `is_censored` フラグを足す**: 移行は軽いが、フラグを見ない利用者が
  必ず出る。公開・MCP 前提では「見なくても間違えない」設計を優先する。却下。
- **検閲値を除外する**: 単純だが、23.4% を捨てることになり「検出されなかった」という
  情報も失う（低濃度であることは重要な情報）。却下。
- **代入済みの値だけを配る**: 利用は楽だが、代入方法を利用者が選べず再現性も落ちる。
  代入は L3 の集計時に、方法を明示して行う。却下。
