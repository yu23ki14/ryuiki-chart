# ADR-0008: 時間は「区間＋粒度」の3点セットで表す

- 状態: 提案中 / 日付: 2026-09-06
- 関連: ADR-0007（observation）, ADR-0011（キューブ）, ADR-0013（caveat）

**2026-09-08 追記（ADR-0021 で拡張）**: `grain` は「日付から確実に言える期間の粒度」
（`period_grain`）であり、「値が代表する統計期間」（`value_grain`。出典側の宣言に由来し、
日付の桁数からは再導出しない）とは別の軸であることが Phase B の実装で判明した
（`atsugi_river_water_quality` のように、値は日間平均値でも日付が年度番号までしか残っていない
出典があるため）。詳細は [ADR-0021](0021-observation-grain-and-cube-key.md)。

## 背景

`measurements.measured_on` には**2つの意味の値が混在**している（実測）。

```
length(measured_on)=10 : 217,710 行   -- '2015-04-08' 検体値（その日に採水した1点）
length(measured_on)=4  : 105,454 行   -- '2015'       年度集計値（日本の年度 4月〜翌3月）
```

現行はこれを `derived` 側で `kind` 列に逃がして区別しているが（`meas_year.kind`）、
原本テーブルの列からは読み取れない。加えて基盤全体では次の粒度が同居している。

- 時刻点（`sensor_timeseries.phenomenon_time`、時別 718k行）
- 日・月・年（派生の `meas_daily` / `meas_month` / `meas_year`）
- 平年値（`zone_clim` / `meas_clim` — 月ごとの多年平均）
- 調査年次（`mammal_mesh.survey_label` — 「第6回自然環境保全基礎調査」のような幅のある期間）
- 年度（fiscal year。`cells.fiscal_year`、`to_fiscal_year()` で正規化済み）

**`'2015'` を ISO 日付として読むと 2015-01-01 になり、日本の年度（2015-04-01〜2016-03-31）
とは3か月ずれる。** MCP クライアントはこれを知らない。

## 決定

**すべての時間を `period_start` / `period_end` / `grain` の3点セットで持つ。単一の日付列を持たない。**

| grain | period_start | period_end | 例 |
|---|---|---|---|
| `instant` | 時刻 | = start | センサー観測 |
| `hour` `day` `month` `year` | 区間の開始 | 区間の終了（**閉区間の終端を明示**） | 日平均・月平均 |
| `fiscal_year` | 04-01 | 翌年 03-31 | 年度集計値 105,454行 |
| `survey_period` | 調査開始 | 調査終了 | 自然環境保全基礎調査の回次 |
| `climatology` | 代表期間の開始 | 終了 | 平年値。別に `climatology_month` を持つ |

- **`'2015'` のような曖昧な文字列を値として持たない。** 取り込み時に
  `grain='fiscal_year', period_start='2015-04-01', period_end='2016-03-31'` に展開する。
  原表記は `period_raw` に残す（収集規約の「原文表記は `*_raw` に残す」に従う）。
- 期間の幅が不明なものは `grain='unknown'` とし、`period_end` を NULL にする。
  **推定で埋めない**（`docs/COLLECTOR_CONTRACT.md` の禁止事項）。
- 集計キューブ（ADR-0011）のキーにも同じ3点セットを使う。年と年度を混ぜて平均しない。
- API/MCP の応答には常に3点セットを含める（ADR-0014）。`year: 2015` だけを返さない。

## 影響

- **良い**: 年度と暦年の取り違えが構造的に起きなくなる。「検体値か年度集計値か」が
  `grain` で読める（`kind` 列の役割がモデルに載る）。粒度をまたぐ集計の可否を機械が判定できる。
  平年値・調査年次のような扱いにくい期間が例外にならない。
- **コスト**: 日付列1つが3列になる。既存の 323,164 行を展開する移行が必要。
  クエリが `measured_on = '2015-04-08'` から範囲条件に変わる。
- **注意**: 年度は地域・組織によって定義が違いうる（会計年度と漁期など）。
  `grain='fiscal_year'` の定義は地域コードリスト（ADR-0002）に持たせる。

## 検討した代替案

- **`kind` 列を原本にも足す**: 最小の修正だが、時刻点・調査年次・平年値を表せず、
  「年度がいつからいつか」は依然としてクライアントの知識に依存する。却下。
- **ISO 8601 の期間表記（`2015-04-01/2016-03-31`）1列**: 表現力は足りるが、
  範囲クエリとインデックスが効かない。却下。
- **すべて日次に展開する**: 比較は楽になるが、年度値を365日に割り振ることになり
  「推測で埋めない」に反する。却下。
