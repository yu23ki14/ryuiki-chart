# ADR-0018: 公開範囲と座標の一般化をデータとして持ち、公開経路で強制する

- 状態: 提案中 / 日付: 2026-09-06
- 関連: ADR-0001（dist）, ADR-0005（ライセンス）, ADR-0013（caveat）, ADR-0014（応答）

## 背景（実測）

希少種の詳細な位置情報の公開は、盗掘・密猟のリスクに直結する（要求定義 FR-4.5 / NFR-8）。
v1 は既にこれを扱っている。

```
organism_records.publication_scope
  全公開    818,684
  限定共有    5,008   ← レッドリスト該当種と完全に一致（RL該当かつ全公開は 0 件）
```

学名で `redlist_assessments` に一致する行のうち `red_list_category` が空のものは **0 件**で、
現時点でこのゲートは漏れていない。**v1 の判定自体は妥当である。**

問題は、この判定の**持ち方**にある。

1. 判定は収集スクリプトの中の一度きりの処理で、**モデル上のルールとして存在しない**。
   新しい出典を足したときに同じ判定が適用される保証がない。
2. 判定は `red_list_category` の**文字列**に依存する。実データのカテゴリ表記は
   `絶滅危惧ⅠB類（EN）` / `絶滅危惧IB類（EN）` / `絶滅危惧IB 類（EN）` /
   `絶滅危惧ⅠＡ類（CR）` / `絶滅危惧IA類（CR）` のように揺れており（ADR-0019）、
   **表記が変われば静かにゲートを通り抜ける**。
3. 座標の精度が分からない。`coordinate_uncertainty_m` は **617,950行（75%）が NULL**。
   「精度が粗いから安全」とは言えない。
4. 公開の粒度が「全公開 / 限定共有」の2値しかなく、**一般化して公開する**
   （メッシュに丸めて出す）という選択肢がない。実際には ADR-0011 のキューブが
   メッシュ集計を作るので、**集計経由で位置が漏れる経路が新たに生まれる**。

## 決定

**公開範囲と一般化の規則をデータとして持ち、`dist/` 生成と API/MCP の両方で強制する。**

```
publication_rule
  rule_id, region_id, scope_kind ('taxon'|'place'|'source_edition'|'variable'),
  scope_ref, action ('publish'|'generalize'|'withhold'),
  generalize_to,      -- 'mesh3' | 'mesh2' | 'municipality' | 'watershed'
  reason, decided_by, decided_on, review_on
```

1. **判定は分類群の属性ではなくルールとして持つ。** 「県または国のレッドリスト掲載種は
   3次メッシュに一般化して公開」をルール1行で表す。新しい出典にも自動的に適用される。
2. **判定の入力はカテゴリ文字列ではなく `taxon_id`**（ADR-0019 で正規化したもの）。
   表記ゆれでゲートを抜ける経路を塞ぐ。
3. **`generalize` を第三の選択肢にする。** 座標を落として place（メッシュ）だけを出す。
   「出す / 出さない」の2値より情報が残り、リスクも下がる。
4. **キューブと集計にもルールを適用する。** メッシュ集計であっても、
   ルールが `withhold` の分類群は集計から除外する。**集計は隠蔽ではない**
   （1メッシュ1件の集計は座標とほぼ等価）。件数が閾値未満のセルの扱いを規則に含める。
5. **精度不明の座標は「精度が粗い」とみなさない。** `coordinate_uncertainty_m` が NULL の
   ものは保守側に倒し、一般化の対象にする。
6. **`dist/` 生成時に強制し、API/MCP でも強制する。** 二重にかける。
   除外・一般化した件数は応答に出す（ADR-0014 の `excluded`）。**黙って減らさない。**
7. ルールには `decided_by` / `review_on` を持たせる。**誰がいつ決めたかが分からない
   公開判断を作らない。**

## 影響

- **良い**: 公開判断がデータとして可視・レビュー可能になる。新しい出典・新しい地域に
  自動的に適用される。一般化という中間の選択肢ができる。
  MCP を公開しても位置情報の事故が起きにくい。
- **コスト**: ルールの初期設定と、対象種の棚卸しが必要。キューブ生成にルール適用の
  段が入り、ビルドが複雑になる。集計セルの閾値の設計判断が要る。
- **リスク**: ルールが厳しすぎると、生物データの公開価値が下がる。
  `review_on` で定期的に見直す前提にする。

## 検討した代替案

- **現行のまま `publication_scope` の2値で運用する**: 追加コストは無いが、
  上記1〜4の穴が残る。特に集計経由の漏れは新設計で新たに生まれる経路なので放置できない。却下。
- **希少種データを一切公開しない**: 最も安全だが、データの価値の相当部分を失い、
  GBIF 公開（FR-4.1）の趣旨にも反する。却下。
- **公開範囲を出典のライセンスに畳む**: ライセンスと保全上のリスクは別の軸で、
  「CC-BY だが位置は伏せる」が表せない。却下。
